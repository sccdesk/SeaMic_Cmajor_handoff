Why Cmajor. The project brief allowed any implementation language; Cmajor was chosen because (a) it JIT-compiles and hot-reloads, so parameter and logic experiments are instant; (b) its cmaj render command gives deterministic offline playback of a patch against a WAV file — exactly the closed loop needed for automated DSP validation; (c) the same code exports to C++ (for integration into SeaTime's hand-written engine) and to WebAudio for demos. The costs accepted were a small, unfamiliar language (two syntax mistakes in the first hour, M1/M2) and a render engine with undocumented quirks (M8).

4. Methodology and Test Bench

The process followed a classic iterative DSP development loop, with one addition that proved decisive: every behavioural claim had to be produced by a measurement, not by listening to the code. Figure 1 shows the loop; it ran roughly 15 times during the session.

4.1 Offline test bench

  1. Stimulus. stimulus16k.wav — 7 s, 16 kHz mono, deterministic (seed 12345): [0–1 s] noise at −50 dB · [1–3 s] quiet speech-like tone cluster at −30 dB (harmonic f0=130 Hz, 4 Hz syllabic AM) with a single 0.8-amplitude transient at 2.5 s · [3–4 s] noise at −40 dB · [4–6 s] loud speech at −6 dB · [6–7 s] noise at −50 dB. This exercises every branch: quiet-speech detection, transient/limiter handling, noise between and after speech, AGC pull-down.
  2. Render. cmaj render SeaMic.cmajorpatch --rate=16000 --blockSize=128 --input=stimulus16k.wav --output=render.wav
  3. Measure. anwav2 reports per-second-segment RMS, true peak and the count of samples strictly above 0 dBFS (the clipping criterion for R4).
  4. Attribute. When a number looked wrong, probe patches replaced the suspect stage with a readable wire (beep / DC-coded SNR / raw level) — the bisect tree of §6.
