6. Development Log: Mistakes, Observations and Corrections

This chapter is deliberately candid: an end-of-year record is only useful if it preserves the failures. Each entry follows the same structure — symptom → hypothesis → probe → root cause → fix → verification — because that is the procedure that actually recovered the project (Figure 5 in §6.9).

M1 — Language syntax: array declarations and the assignment operator Symptom. First dry-runs failed to compile: error: Found "[" when expecting ";" on float ring[512];, later Found "<-" when expecting ";" on float x <- in;.
Root cause. Cmajor declares fixed arrays size-first (float[512] ring;) — the C order is invalid; and <- is reserved for writing output streams (out <- v;), while state and locals use plain =, including reading streams (float x = in;).
Fix. Corrected all declarations/assignments; recorded the rules in the session README before writing further code.
Verification. cmaj play --dry-run → Loaded: ….
M2 — Hoisted value endpoints are uninitialised under headless render Symptom. The graph declared input vad.enterDb; / input vad.exitDb; hoisted from the VAD's input value float … [[init: 9.0]] endpoints. In the GUI player the defaults apply; under cmaj render there is no controller to deliver them, so the endpoints can read 0 — making enter = exit = 0, which collapses the hysteresis (noise enters instantly, exit fires instantly). A related edit also produced Cannot find symbol 'enterDb' when the node endpoint name didn't exist.
Probe. Compile-and-render attempts of the probe patches; one hypothesis test (SeaMicValueProbe) contrasted a value-endpoint threshold against a plain float.
Root cause. Endpoint delivery model: value endpoints are driven from the host, not self-started.
Fix. VAD thresholds became plain state floats (enterDb = 9.0f; exitDb = 4.0f;) inside chain2; only AGC knobs (whose host defaults are safe) remain hoisted. A graph-level node vad = VAD(9.0f,4.0f) attempt also failed — VAD declares no specialisation parameters — confirming the thresholds belong to state, not template arguments.
Verification. All three production patches compile warning-free and render identically with or without GUI.
M3 — Phantom-SNR at boot: the floor initialised below reality (most serious DSP bug) Symptom. Offline renders of chain v1 (measured before the analyzer bug M7 was known — treat magnitudes as indicative) showed inverted behaviour in both directions: false-on at boot — the detector latched "speech" during the first all-noise second and the AGC, believing speech, adapted its full +30 dB range on noise, which then leaked through the open gate (noise segments emerging at speech-like level); and false-off on the quiet talker — the −34 dBFS quiet speech failed to hold detection and came out heavily attenuated.
Evidence (solid — independent tool). A per-100 ms SNR/floor trace of the stimulus (vadprobe, which reads the 16-bit stimulus directly and was unaffected by M7) showed the floor sitting at its −80 dBFS initialisation while the seg0 noise measured −54.8 dBFS: a +25 dB phantom SNR on pure noise at t = 0, far above the 12 dB enter threshold. Worse, the v1 floor was allowed to rise with an upward leak, so during the quiet speech it drifted up toward the speech level, SNR collapsed to ~0 dB, and detection exited and stayed off — while the boot false-on had already frozen sub-block updates (they were gated on speech-presence, M4), leaving a corrupted reference for the rest of the file.
Root cause. Initialising a minima-tracker below the expected floor plus allowing it to rise creates guaranteed false triggers at power-on — the stakeholder's predicted weakness of threshold heuristics, realised in our own code.
Fix. Boot the floor at the −40 dBFS cap and make it lower-only for life (boot: instant-min track downward; runtime: minimum over the sliding window). Real floors (−50 dBFS and below) are now always reached by falling; SNR on noise at boot is ≤ 0 dB.
Verification. Re-render: seg0/seg6 noise no longer enters; quiet-speech segments open.
M4 — Sub-block rotation frozen during speech Symptom. Even after M3's fix the flag-beep probe opened only from seg3 onward (quiet speech in seg1–2 stayed dark in early probe runs).
Hypothesis → probe. With M7 excluded at that time, the bisect pointed at estimator state evolution. Inspection of the rotation block showed the whole 1 s sub-block rotation wrapped in if (isSpeech < 0.5): on a speech onset, rotation stopped until speech ended, so the 3 s window could not slide, curSubMin never reset correctly, and a stale floor persisted for up to 3 s after each utterance.
Root cause. Conflating two different policies: speech must not contribute new minima — true — with the window must not slide during speech — false.
Fix. Rotate always; in the speech branch substitute the current floor for the sub-block minimum (subMinA = noiseFloor), which carries the last known noise estimate forward without letting speech write into it (Figure 4).
Verification. Probe rendering shows the window refreshing across segment boundaries; no more multi-second stale-floor episodes.
