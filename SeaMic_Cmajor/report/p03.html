1. Introduction and Problem Statement

1.1 Context

SeaTime is a meeting application in which audio is encoded with the Xiph Opus codec at a 16 kHz sampling rate (speech band). The microphone path previously exposed two sliders to the end user — microphone gain and activation threshold — plus a one-second shutoff hysteresis based on instantaneous RMS. User research against mainstream competitors (Microsoft Teams, Zoom) showed that these controls are never touched by average users, who nevertheless suffer when the defaults are wrong: distant or quiet talkers disappear, and background noise opens the gate and gets amplified.

The product decision was therefore to remove both sliders and move all adaptation automatically into the DSP: an adaptive activation threshold and an online loudness-normalisation stage. This report documents how that requirement was translated into a concrete signal chain, how the chain was implemented and validated, and — because a faithful engineering record must include failure — every significant mistake made along the way and the evidence-driven procedure used to correct it.

1.3 Objectives

  • Main objective: deliver a compilable, real-time-capable Cmajor patch implementing the full adaptive chain (DC → K-weight → VAD → AGC → gate → limiter), verified offline by rendering and online by live microphone playback.
  • Secondary objectives: build a reusable offline test bench (stimulus generator + segment analyzer + probe patches); document the design arguments that resolved contested architectural questions; produce this report as the durable record of the iteration.

1.4 Summary of contributions

  1. Sidechain-split chain architecture with the measure-pre-gain / apply-pre-gate ordering.
  2. A rate-agnostic min-statistics VAD (cap-booted, lower-only floor, 3×1 s sliding minima, hysteresis, hangover, flatness exit) tuned for 16 kHz speech.
  3. A probe-based bisect methodology (nine probe patches) that separated engine quirks, tooling bugs and genuine DSP defects — and the discovery that the offline analyzer itself was misparsing rendered files.
  4. A verified live MVP on real WASAPI hardware plus a documented manual test protocol.
