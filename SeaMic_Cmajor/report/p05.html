2.4 Voice Activity Detection and min-statistics noise estimation

Energy-based VAD decides speech presence by comparing short-term energy against an estimate of the noise floor. The decision itself is trivial; the hard part — and the reason the original hand-tuned threshold slider existed at all — is that the floor drifts (HVAC, fan, room tone, keyboard). The classical robust solution is minimum statistics [5][6]: within a sliding window that is long enough to contain at least one true noise-only interval (typically 1–3 s), the minimum of the smoothed energy estimates the noise power even while speech occupies most of the window. From that floor, a signal-to-noise ratio drives a hysteresis pair:

SNRdB = 20 log10(Efast / Enoise);   enter if SNR > Ton, exit if SNR < Toff,   Ton > Toff

Three refinements implemented here go beyond the textbook sketch:

  1. Lower-only floor. The estimator may only decrease the floor during operation (the sub-block window always slides, speech never contributes new minima, and the running floor takes the minimum of the window). This removes the failure mode where a speech onset is misread as a rising floor — the root cause of the first serious bug in this project (M3, §6).
  2. Cap-booted initialisation. The floor starts at a fixed −40 dBFS ceiling and can only fall. Starting too low (the natural mistake: start at digital black) manufactures phantom SNR at power-on and falsely triggers on pure noise; starting at a known upper bound guarantees that every real floor is reached by falling.
  3. Flatness (crest) exit. Stationary broadband noise can out-wait pure SNR hysteresis if the floor sits slightly below it. A secondary test — after a 1.5 s grace period, force an exit when SNR stays under 3 dB for 600 ms — specifically defeats "fan lock-on" while ignoring the natural amplitude modulation of real speech.

A hangover counter (600 ms in the final version, per the stakeholder request for longer hold) bridges inter-word pauses so gate chatter never chops syllables.

Design argument #2 — why not RNNoise? A DNN speech/noise classifier (RNNoise [7]) was proposed as the alternative to heuristic thresholding. Trade analysis: RNNoise is small by modern standards (≈0.5–2 MB float, ≈5–10 MMACS) but it is a denoiser whose VAD output is a by-product; it mandates a 10 ms frame cadence and its own latency, and it still requires an AGC stage — so it would add a model dependency without solving the actual problem (gain adaptation). For stationary noise — the dominant failure case — statistics win: the min-statistics VAD costs a few kilobytes of code and no model files (requirement R6). A DNN remains the right tool only when non-stationary interference (babble, keyboard) must be suppressed — future work.
